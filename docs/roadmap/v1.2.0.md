| 项 | 内容 |
|----|------|
| **产品版本** | `v1.2.0`（规划中） |
| **前置依赖** | `v1.1.0` 正式（至少完成 alpha3 数据可信 + beta 季节分类） |
| **文档状态** | Roadmap（未开发） |
| **上一版规划** | [v1.1.0.md](./v1.1.0.md) |

> **禁止提前开发。** 须先完成「数据准确性 → 分类基础」，再做本版「AI 识别 → AI 推荐」。详见 [roadmap README](./README.md)。

---

## 1. 版本目标

在衣橱数据可信、季节等标签可用的前提下，交付 **AI 衣橱助手**：打卡照片能认、能匹配已有衣物，今日穿搭推荐有依据、避免随机。

一句话：**先认准、再匹配、再推荐；不用骰子代替衣橱。**

---

## 2. 功能列表

### 2.1 AI 识别打卡照片

- 用户上传今日穿搭照片
- AI 识别衣物 **类别、颜色、风格**（等可结构化字段）
- 为自动匹配提供输入（替换 v1.0/v1.1 的 `simulateMatch` 占位）

### 2.2 自动匹配衣橱

- 将识别结果与衣橱已有衣物做相似匹配
- 示例：AI 识别「黑色针织衫」→ 提示 / 勾选衣橱中相似单品
- 匹配失败时降级：用户可手动从衣橱挑选（保留现有手动路径）

### 2.3 AI 今日穿搭推荐

依赖（缺一则不应上线「智能推荐」宣称）：

- 衣物标签
- 季节（`season`，来自 v1.1.0-beta）
- 历史穿着
- 用户偏好

要求：

- **避免随机推荐**
- 推荐结果可解释（至少能落到上述依赖维度之一）

## 3. 优先级与依赖

```text
v1.1.0-alpha3 数据准确性
    → v1.1.0-beta 分类基础（季节等）
        → v1.2.0 AI 识别打卡照片
            → 自动匹配衣橱
                → AI 今日穿搭推荐
```

| 优先级 | 模块 | 依赖 |
|--------|------|------|
| P0 | AI 识别打卡照片 | Vision 能力；打卡上传链路稳定 |
| P0 | 自动匹配衣橱 | 识别结果 + 衣橱结构化字段 |
| P1 | AI 今日穿搭推荐 | 标签、季节、历史穿着、偏好就绪 |

---

## 4. 明确不做（本版边界）

- 不在数据口径未修、季节未落地前启动本版开发
- 不做复杂命理黄历（灵感能力属 v1.1.0-beta，且保持轻量）
- 不默认要求用户自备 API Key（延续 Worker AI Proxy，除非产品另有决策）

---

## 5. 验收标准（草案）

### 5.1 识衣打卡

- [ ] 上传穿搭图后得到类别 / 颜色 / 风格等结构化结果（可编辑纠错）
- [ ] 不再依赖随机 `simulateMatch` 作为主路径

### 5.2 匹配

- [ ] 识别「黑色针织衫」类描述时，能列出衣橱相似候选
- [ ] 无候选时可手动挑选，流程不中断

### 5.3 推荐

- [ ] 推荐显式使用标签 / 季节 / 历史 / 偏好中至少一组真实信号
- [ ] 同输入下不表现为无依据的纯随机套装
- [ ] 用户可理解「为何推荐」（简短说明即可）

### 5.4 发版门槛

- [ ] 更新 `docs/versions/v1.2.0.md`
- [ ] Git tag + Vercel Production 验证
- [ ] 回归 v1.1.0 打卡闭环、Vision 添衣、分析口径、季节浏览

---

## 6. 风险

| 风险 | 等级 | 缓解 |
|------|------|------|
| 识别不准导致错勾 | 高 | 预览确认；低置信度不强勾；保留手动 |
| 匹配阈值难调 | 中 | 可调阈值 + 多候选；人工覆盖 |
| 推荐过早上线 | 高 | 严格依赖季节与历史；未就绪不开入口 |
| 范围蔓延（搭配社交等） | 中 | 本版只做识衣·匹配·今日推荐三条 |
