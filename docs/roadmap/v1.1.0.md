## 2. v1.1.0-beta2 — 智能衣橱数据可信增强版

**标题：** 智能衣橱数据可信增强版  

**一句话：** 购入日期可信、穿着统计可信、分析页无陈旧缓存；为后续 AI 推荐打牢数据基础。

### 2.1 P0：订单日期规则优化

**目标：** 修复 AI 订单识别日期不准确问题。

**规则：**

1. **AI 或用户输入包含明确年份**（例如 `2025-08-15`）  
   → **优先保留识别年份**，不得仅因「不是当前年」就强行改成当前年。

2. **只有月日**（例如 `08-15`）  
   → 使用 **当前年份** 补全。

3. **异常年份 → 人工确认，不自动修正**  
   若识别到明确年份，但落在明显异常范围（例如远超合理购衣区间、明显笔误/乱码年等），**不得静默改写为当前年或其他猜测值**；应在预览中保留识别结果（或明确标出待确认），交由用户核对后手动修改。

4. **预览 / 编辑表单始终允许用户手动修改**日期，并以用户最终确认值为准入库。

**验收：**

- [ ] 无年份订单：补当前年，表单可见
- [ ] 有年份订单（正常）：保留识别年份，不被改成当前年
- [ ] 有年份但异常：进入人工确认路径，系统不自动修正年份
- [ ] 手动修改日期后保存正确
- [ ] 不回归 beta1 及之前添衣 / Vision / 打卡路径

---

### 2.2 P1：分析统计口径修正

**目标：** 让分析数据可信。

#### 穿着 TOP

- **只基于** 真实穿着记录：`logs`
- **不基于：** 创建时间、收藏、推荐生成记录等非穿着信号

#### 「暂无穿着」与「闲置」（必须区分）

| 分类 | 定义说明 |
|------|----------|
| **暂无穿着** | 尚无有效穿着行为：典型为新入库、或 `logs` 中穿着次数为 0。表示「还没穿过」，**不是**闲置评判对象。 |
| **闲置** | 在已有穿着基础或已持有一段时间的前提下，**长期未再穿着** 的衣物。语义是「拥有较久却很少穿 / 很久没穿」，用于提醒周转，而非惩罚新衣。 |

**关系说明：**

- 「暂无穿着」与「闲置」互斥归属：零穿着新衣 → **暂无穿着**；不得因「没穿过」直接标为闲置。
- 「闲置」需同时体现 **持有时长 / 未穿间隔偏长** 这类语义；具体天数或阈值 **不在本 roadmap 写死**，实现时再定可调口径，并在发版记录中说明。
- **避免：** 新衣刚入库就显示「闲置」。

**验收：**

- [ ] TOP 仅统计 `logs` 真实穿着
- [ ] 0 次穿着进入「暂无穿着」，与「闲置」列表分离展示（或等价可区分）
- [ ] 新入库未穿过的衣物 **不会** 被标为闲置
- [ ] 「闲置」文案/口径体现长期拥有且长期未穿；不写死固定天数进产品硬编码（或仅作可配置实现细节）

### 2.3 P1：分析数据刷新

**目标：** 衣物新增、编辑后，分析页数据始终最新。

- 重新进入分析页时展示最新统计
- **不出现** 旧缓存 / 陈旧数字

**验收：**

- [ ] 新增衣物后进入分析页，统计已更新
- [ ] 编辑衣物（含淘汰等）后进入分析页，统计已更新
- [ ] 同会话内离开再进入分析 Tab，无陈旧缓存感
