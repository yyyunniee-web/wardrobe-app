## 版本原则（本系列适用）

开发顺序必须遵守：

```text
数据准确性 → 分类基础 → AI 识别 → AI 推荐
```

- **不要提前开发推荐功能**（含打卡真实识衣匹配、AI 今日穿搭推荐）
- 推荐依赖的数据与分类基础未就绪前，禁止开工 `v1.2.0` 推荐项
- Worker AI Proxy 协议、无关大改 UI，非验收阻塞不改

## 2. v1.1.0-alpha3 — 数据可信度优化

**主题：** 让购入日期与穿着统计可信，分析页数字可解释。

### 2.1 AI 订单日期解析修复

- **有明确年份：** 使用识别到的年份，不得强行改成当前年
- **无年份（仅月日等）：** 用 **当前年份** 补全
- **保留** 用户在预览/编辑表单中的手动修改能力
- 入库前保持现有核对提示

### 2.2 数据分析优化

- **穿着 TOP** 只统计真实穿着记录（以 `logs` 等有效穿着为准，口径在实现中写清）
- **0 次穿着** 衣物归类为 **「暂无穿着」**
- **不允许** 新衣（或从未穿过）直接进入 **「闲置」**

### 2.3 分析数据实时刷新

- 新增衣物后，相关统计 **自动更新**（或约定时机立即失效重算）
- 返回 / 进入分析页时，保证展示为 **最新数据**

### 2.4 alpha3 验收清单

- [ ] 仅月日、无年份 → 补当前年，表单可见可改
- [ ] 含明确年份 → 默认使用该年，不被改成当前年
- [ ] 至少覆盖：无年订单、有年订单各 1 组样例
- [ ] 穿着 TOP 仅基于真实穿着记录
- [ ] 零穿着进入「暂无穿着」，不进闲置
- [ ] 新入库未穿过的衣物不会被标为闲置
- [ ] 新衣入库后 / 回到分析页，统计为最新
- [ ] `npm run build` 通过；不回归 alpha1/alpha2 打卡与 Vision 路径

### 2.5 alpha3 明确不做

- 衣橱季节导航重构、每日穿搭灵感（→ beta）
- AI 识衣打卡、自动匹配衣橱、AI 穿搭推荐（→ v1.2.0）

## 3. v1.1.0-beta — 衣橱体验完善

**主题：** 分类基础 + 轻量每日灵感；为后续 AI 推荐准备数据，**本阶段不做推荐引擎**。

### 3.1 衣物季节分类

新增 / 强化衣物属性：**season**（可与现有季节标签对齐，产品名以 `season` 为准）

支持取值：

- 春
- 夏
- 秋
- 冬
- 四季

要求：

- **不强制** 用户填写
- 支持 **多季节**
- 为未来 AI 推荐提供基础数据（本 beta **不实现** 推荐）

分类结构（衣橱浏览示意）：

```text
衣橱
 └ 上衣
    ├ 春
    ├ 夏
    ├ 秋
    └ 冬
```

（其他品类同理；无季节的衣物有合理落位，如「未分类 / 全部」。）

### 3.2 每日黄历 / 穿搭灵感

- **默认开启**，用户可关闭
- 每日最多显示 **前三条**
- 语气轻量，不做完整黄历、不做复杂命理

示例：

```text
今日穿搭灵感

宜：
- 简约
- 清爽
- 通勤
```

### 3.3 beta 验收清单

- [ ] 衣物可维护 season（多选）；可不填也能入库/编辑
- [ ] 衣橱可按品类 → 季节浏览（结构符合上述示意）
- [ ] 今日穿搭灵感默认展示；设置中可关闭
- [ ] 每日灵感条数 ≤ 3；无命理/完整黄历堆砌
- [ ] 不引入 AI 推荐 / 打卡识衣（仍用既有占位）
- [ ] `npm run build` 通过；不回归 alpha 数据可信度与打卡/Vision

### 3.4 beta 明确不做

- AI 识别打卡照片、自动匹配衣橱、AI 今日穿搭推荐（→ v1.2.0）

## 5. 风险（剩余阶段）

| 风险 | 等级 | 说明 | 缓解 |
|------|------|------|------|
| 日期规则边界 | 中 | 仅月日 vs 有年份易漏；跨年订单 | 样例验收；表单可手改 |
| 分析口径变更 | 中 | TOP / 闲置 / 暂无穿着数字变化 | 文档 + UI 文案区分 |
| 季节与历史数据 | 中 | 旧衣无 season | 可选字段；默认「全部」可见 |
| 灵感内容质量 | 低 | 文案空洞或过重 | 固定轻量模板；可关闭 |
| 范围蔓延到推荐 | 高 | beta 易顺手做匹配/推荐 | 硬性归属 v1.2.0；本版禁止 |
