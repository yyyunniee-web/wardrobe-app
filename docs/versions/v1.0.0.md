## 本版本目标

交付第一个可长期使用的正式产品基线：衣橱云端管理、AI 订单截图录入（用户无需 API Key）、通用图片编辑/裁剪、打卡与分析基础能力、可安装的 PWA，并固定可回滚的 Git 标签。

---

## 已实现功能

### 衣橱管理

- 添加 / 编辑 / 删除衣物；淘汰与恢复
- 品类浏览、搜索筛选、多维排序
- 图片上传与表单内图片编辑入口
- 单件 / 全量导出；设置页备份导入导出

### AI 订单识别

- 订单截图 → 视觉解析 → 预填表单 → 核对入库
- 多商品选择防串件
- Worker AI Proxy（`POST /ai/vision`），生产用户无需填写 Key

### 图片上传 / 裁剪

- 统一 `/upload-image` 上传
- AI 订单自动裁剪（左侧缩略图启发式）
- 通用手动裁剪（保留会话原图；取消不改预览）
- 菜单：裁剪图片 / 重新上传 / 取消

### 打卡

- 穿搭打卡（拍照或手动选衣）、心情打卡
- 穿搭日记（筛选、左滑删除、详情）
- 规则化今日穿搭推荐可写入打卡
- **占位**：有照片时的衣物匹配仍为随机 UI，非真实 AI 识衣

### 今日页

- 资料展示、城市天气（今日/明日）、穿衣提示、黄历宜忌
- 心情入口、日记与推荐入口

### 分析

- 购入日期与标签筛选（云端持久化）
- 穿着 Top、闲置、价值交叉等统计

### PWA

- Manifest standalone 安装、Service Worker 壳缓存（network-first）
- iOS/Android 安全区与更新检查相关能力

### 数据同步

- Cloudflare Worker API：衣物、资料、打卡、日志、场景、筛选等
- 图片云端存储；前端离线变更队列（上传一般不入队）

## 技术架构

| 层 | 说明 |
|----|------|
| 前端 | Vite + TypeScript；入口 `index.html` → `src/wardrobe/main.ts`；主 UI 为 vanilla DOM |
| 数据层 | `src/utils/request.ts` + `src/stores/dataStore.ts` |
| API | `https://wardrobe-api.yyyunniee.workers.dev`（Worker 源码不在本仓） |
| AI | 浏览器 → Worker `/ai/vision` → 视觉模型（Key 在服务端） |
| 图片 | `POST /upload-image` → 对象存储 URL（推断 R2，细节需 Worker 侧确认） |
| 部署 | 前端 Vercel（push `main`）；PWA 静态资源在 `public/` / `dist/` |
| 天气 | Open-Meteo（浏览器直连，非 Worker） |

衣物远端模型约定：`id, name, tags[], photo_url, notes`（`notes` 为 JSON 扩展字段）。

## 已知问题

1. 打卡照片识衣仍为随机占位，真实 AI 识衣属后续版本  
2. Manifest 仍有「数据不上云」过时文案  
3. 裁剪原图不入库，关表单后无法还原裁剪前原图  
4. `outfit` 等资源有同步、缺少独立 UI  
5. 部分 profile 字段无完整设置入口；`@supabase/supabase-js` 未使用  
6. React 脚手架文件存在但非主应用入口  
7. Worker / D1 / R2 实现细节以线上为准（本仓不可见）  
8. iOS PWA 安全区等问题已修，发版后仍建议真机回归
