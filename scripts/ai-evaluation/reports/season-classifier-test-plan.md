## 1. 当前 season 实验结论

| 项 | 内容 |
|----|------|
| 实验 | `run-season-rule-eval.ts`：用 label.`purchaseDate` 按月映射季节 |
| 规则 | 12–2 冬 / 3–5 春 / 6–8 夏 / 9–11 秋 |
| 结果 | **4/4 mismatch**（相对现有人工 label） |
| 解读 | **不能**据此否定「季节字段」本身，也**不能**据此把「购买月 → season」定为产品主规则 |

**可落地的中间结论（评测侧）：**

1. 现有 4 张订单图的 label.`season` 更接近「穿着/品类季节」或「全年」，而非「下单月份季节」。
2. `purchaseDate` 适合作为 **OCR 提取的事实字段**；不宜单独充当 season 的充分条件。
3. 下一步应评测 **多源 season 分类器**，而不是继续优化「买时推季」。

## 2. 样本偏差分析（当前 4 图）

| case | 购买月 | 规则推季 | label | 偏差类型 |
|------|--------|----------|-------|----------|
| bra_001 | 12 月 | 冬 | 夏 | **全年品类**（内衣）被人工标成穿着感；或标签口径不一致 |
| shorts001 | 10 月 | 秋 | 全年 | **全年品类**（内裤）；规则无法表达「全年」 |
| shoes-001 | 4 月 | 春 | 夏 | **强季节商品 + 提前购**（洞洞鞋/凉拖） |
| tshirt_001 | 5 月 | 春 | 夏 | **边界月**（5→春 vs 夏穿着预期）；单点不能外推 |

**偏差含义：**

- 当前集 **过拟合「订单截图 + 内衣/凉拖/T 恤」**，缺少冬装、强冬夏对立样本。
- 「全年类」若无独立标签值（或 Vision 枚举无「全年」），任何纯月份规则都会系统性误判。
- 提前购使 **purchaseDate 与穿着季错位**；应用属性（品类/名称/材质）优先，日期仅辅助。

## 3. 新评测目标：season 最佳来源对照

在 **AI Eval 框架内**（仅 `scripts/ai-evaluation/`）对比三路，**不接生产**：

### A. Vision 直接预测 season

- 输入：订单/商品/单品图  
- 输出：模型 JSON 中的 `season`（可用生产 Prompt 或评测 Prompt 副本）  
- 关注：空值率、枚举越界、同图波动（可复用稳定性协议）

### B. 根据商品属性预测（规则 / 轻量分类，评测实现）

输入信号（来自 Vision 结果或人工 gold 属性，实验时需固定来源并写明）：

- `category`
- `subCategory`（若生产暂无，评测 label 可先人工填）
- `material` / `fabric` / `fabricList`
- 商品 `name` 关键词（羽绒、泳、凉鞋、风衣、针织…）

输出：`春` / `夏` / `秋` / `冬` / `全年`（评测枚举建议含「全年」）

### C. 综合预测

优先级建议（评测假说，待测）：

1. 强属性命中 → 锁定（如羽绒服→冬，泳衣→夏，内衣/袜/打底→全年）  
2. 中等属性 + 名称关键词 → 春/秋/夏/冬  
3. **`purchaseDate` 仅作辅助**（例如属性模糊时微调，或与属性冲突时不覆盖强季节）  
4. 仍不确定 → 空或「全年」（策略需在实验里二选一并固定）

## 4. 新评测数据集要求

**原则：** 人工准备图片 + label；禁止抓取线上用户数据。  
**建议目录（未来实现时再建，本方案不落库）：**

```text
datasets/season-classifier/
  images/
  labels/   # 含 season gold + 可选 category/fabric/name
```

### 4.1 品类配额（最低可行集）

| 目标 season | 示例商品 | 最少张数（建议） |
|-------------|---------|------------------|
| **冬** | 羽绒服、大衣、毛衣 | 各 ≥2，共 ≥6 |
| **夏** | 短袖 T 恤、凉鞋、泳衣 | 各 ≥2，共 ≥6 |
| **春秋** | 风衣、薄外套、针织衫 | 各 ≥2，共 ≥6（label 可用 `春`/`秋` 或约定 `春秋`） |
| **全年** | 内衣、袜子、基础打底 | 各 ≥2，共 ≥6 |

**合计建议 ≥24 张**；首轮 MVP 可各季 ≥3 张（≥12）再扩。

### 4.2 Label 字段（gold）

每张至少：

```json
{
  "season": "冬|夏|春|秋|全年",
  "category": "",
  "name": "",
  "fabric": "",
  "purchaseDate": "",
  "notes": "是否提前购/订单截图/单品图"
}
```

- `season`：**穿着/适用季 gold**（产品口径），不是购买月映射结果。  
- `purchaseDate`：有则填（OCR 可另测）；用于 C 臂辅助，**不作为 A/B 的必要条件**。  
- 全年类必须显式标 `全年`，避免再与夏/冬混淆。

### 4.3 分层抽样要求

- **强季节：** 冬/夏核心单品，名称或品类几乎无歧义。  
- **弱季节 / 全年：** 内衣、袜、打底，用于测误判率。  
- **错位购：** 至少 2～4 张「夏装非夏季购买」或「冬装非冬季购买」，专门打 C 臂是否错误被日期带偏。

## 5. 未来评测指标

| 指标 | 定义 | 用途 |
|------|------|------|
| **season accuracy** | `pred == gold` 的比例（全测试集） | 总览 A/B/C |
| **全年类误判率** | gold=`全年` 且 pred≠`全年`（且非空）的比例 | 防止内衣等被标成夏/冬 |
| **强季节商品准确率** | 在羽绒服/大衣/毛衣/短袖/凉鞋/泳衣等子集上的 accuracy | 验证主路径是否可靠 |
| （建议附加）**日期干扰率** | 错位购子集上，C 相对 B 变差的比例 | 证明 purchaseDate 只能辅助 |
| （建议附加）**空值率** | pred 为空的比例 | Vision 臂稳定性 |

报告形态（未来实现时）：`reports/season-classifier-eval.md`，按 A/B/C 分列指标；**本文件只定方案**。
